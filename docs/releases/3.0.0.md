# OncoTracer 3.0.0 release preparation

ONT variants now use dynamic CPU/RAM scheduling by default. As samples finish,
Clair3 CPU chunk queues and independent QUILT2 chunks can use their freed capacity,
within the configured analysis budget and current CPU/container/RAM limits.
Running chunks retain their settings. Reduced allowances delay new work.

Choose `--resource-mode fixed`, `variant_resource_mode: fixed`, or **Keep initial
allocations** in browser/terminal setup to retain the previous scheduling.
An omitted CLI option respects saved YAML. See [resource scheduling](../ont_imputation.md#share-available-cpu-and-ram)
for scope, admission estimates and live status files.

QUILT2 uses its unchanged scientific worker for chunk computation and final
validation/publication. Completed chunk receipts remain compatible. Clair3's
models, caller arguments and completed-output checks remain in place. Full
prepared-reference hashes are shared between chunk prefetch and final validation only within the
same process. A changed path, device, inode, size, modification time or change
time requires hashing again. Recent writes and patient output files are always
hashed in full; no persistent hash cache authorizes reuse. Dynamic
mode bounds sample concurrency by CPU/RAM; independent analyses still need
separate budgets. GPU and scientific analysis stages retain their existing scheduling.

Illumina resume validation uses the selected sample concurrency. The first
sample completes shared preparation before the remaining samples are checked
in bounded worker slots. The terminal reports each validated sample and the
completed/total count. All selected samples must pass before analysis starts;
validation failures stop admission and cancel outstanding checks. Every input,
output and scientific parameter receives the same validation as serial mode.

GISTIC eligibility is checked after CNA coverage QC and report sample selection.
Only unique samples present in the selected full/events SEG count toward the
minimum (at least two). An undersized cohort records a skip, even with
gistic_required enabled, and report generation continues. The eligibility JSON
records included samples, exclusion reasons and the effective minimum. Tool and
result failures in eligible cohorts retain their failure handling. Unassessable
CNA profiles keep their QC labels and incomplete scientific-assessment status.

Long-running steps print bounded progress messages and elapsed times, including
project and installed-environment verification before checkpoint checks. Cohort
merging exposes preparation, merged variant counts, indexing, record validation
and publication. QUILT2 reports verified/total chunks, reused and recomputed
counts, and the final validation/ligation phase. Progress threads stop with
their owning command, and verified
predecessor cohort outputs remain reusable.

Compact storage remains the default, and cohort VCF merging remains optional.
Standalone, wheel/sdist, Conda, Poetry, Docker and the Nextflow manifest share
application version `3.0.0`. Docker can reuse dependency layers across changes
to application release metadata. Scientific environment definitions, bundled
GLIMPSE2/QUILT2 workers and the authenticated Nextflow runtime remain unchanged.

The optimization PR waits until all current OncoTracer jobs finish. Stable
publication also requires full local output validation and successful Native v2
CI plus both full CNA parity workflows for the exact release source on main.
Local tests and candidate artifacts do not satisfy those publication gates.

The completed Illumina merge manifests from the immediate predecessor remain
reusable after verifying every input identity and the complete VCF/index checksums.
Only that reviewed implementation digest is accepted; arbitrary older manifests
must be regenerated. Progress receipts never authorize reuse.

The local resource recorder stops after all observed services finish, even when
systemd unloads a completed unit. An idle terminal shell after the final exit
message is not an analysis process. Progress threads stop with their command.

Saved native 2.3 projects migrate to 3.0.0 when continued. The owned project and
run locks are checked, configuration is backed up, and `config/resume.json` keeps
the previous/selected runtime identities and migration history. Checkpoint files
are preserved; every stage still verifies its inputs and output integrity before
reuse. Other major-version transitions remain blocked.

The local release validator preserves previous candidate binaries and their
provenance before rebuilding an invalidated stage during `--resume`.

Podman is selectable in install, doctor, run, browser/terminal setup, saved-project
continuation and the Nextflow entry. It shares the Docker image, input binding,
preflight and output checks. Rootless execution preserves the invoking UID/GID;
GPU access uses NVIDIA CDI and the existing shared admission policy. See
[Podman installation](../installation_details.md#podman-300-candidate).

FFPE report resume preserves an existing review warning when the HTML redirect
still points to its exact generated target. Rebuilding a report no longer fails
because that warning precedes the redirect marker. Unknown regular files and
modified targets remain protected; the warning and its modification time are
retained on an unchanged resume.


New projects explicitly select `cna_profile: sensitive` in command-line, browser
and terminal setup. Existing projects without the setting continue with
`standard`; `--cna-profile sensitive` explicitly selects the new profile for a
run. Docker, Podman, Conda, Poetry and the full Nextflow entry forward the same
choice. The new profile requires at least 5,000 usable reads, 100 usable bins,
a median of five reads per bin, at most 20% empty bins and at least 99% finite
normalized values. Empty and unusably sparse samples remain not assessable.

Controls, sparse study samples, and calls admitted only by the relaxed size or
amplitude thresholds additionally need supporting raw read depth:
matched GC/mappability bins, enough observed and expected reads, an uncertainty
interval beyond the effect margin, and consistent direction across interleaved
bins and consecutive blocks. Every retained/rejected event has a decision table;
unfiltered calls are preserved in diagnostics. These checks reuse the same reads
and are a heuristic, not independent confirmation or a calibrated error rate.
Only retained events feed final CNA plots and event-based downstream analyses.
The experimental broad screen stays separate from primary CNA calls. See
[CNA evidence assessment](../cna_evidence_assessment.md) for thresholds and limits.

A local comparison on all 22 ONT libraries completed counting, refinement and
CNA plotting using the existing BAMs. Seven passed the sensitive primary coverage
gate, versus one with the standard profile. The initial comparison produced 76 candidate events; all decisions are retained
in an audit table. All five controls failed the primary coverage gate; four
could be screened for broad changes and had no supported change, while one was
unusable. This is a local comparison, not a sensitivity/specificity benchmark or
a completed stable-release validation. Full project continuation and release
parity remain separate gates.

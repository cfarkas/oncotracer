# OncoTracer 2.3.2 release preparation

ONT variants now use dynamic CPU/RAM scheduling by default. As samples finish,
Clair3 CPU chunk queues and independent QUILT2 chunks can use their freed capacity,
within the configured analysis budget and current CPU/container/RAM limits.
Running chunks retain their settings. Reduced allowances delay new work.

Choose `--resource-mode fixed`, `variant_resource_mode: fixed`, or **Keep initial
allocations** in browser/terminal setup to retain the previous scheduling.
An omitted CLI option respects saved YAML. See [resource scheduling](../ont_imputation.md#share-available-cpu-and-ram)
for scope, admission estimates and live status files.

QUILT2 uses its unchanged scientific worker for chunk computation and final
validation/publication. Completed chunk receipts remain compatible. Clair3's
models, caller arguments and completed-output checks remain in place. Dynamic
mode bounds sample concurrency by CPU/RAM; independent analyses still need
separate budgets. GPU and other pipeline stages retain their existing scheduling.

Compact storage remains the default, and cohort VCF merging remains optional.
Standalone, wheel/sdist, Conda, Poetry, Docker and the Nextflow manifest share
application version `2.3.2`. Scientific environment definitions, bundled
GLIMPSE2/QUILT2 workers and the authenticated Nextflow runtime remain unchanged.

The optimization PR waits until all current OncoTracer jobs finish. Stable
publication also requires full local output validation and successful Native v2
CI plus both full CNA parity workflows for the exact release source on main.
Local tests and candidate artifacts do not satisfy those publication gates.

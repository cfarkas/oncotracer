# OncoTracer 2.3.1 release preparation

Compact work storage is the default for Illumina GLIMPSE2 analyses in the
standalone executable, Python/Conda installation, Docker, Apptainer, terminal
setup, browser setup and Nextflow gateway. Completed phase tasks can retire
their generated split-reference binaries after output and provenance checks.
Raw inputs, reference caches, BCF/CSI outputs, logs and resume metadata remain.
Failed, running, altered, shared or uncertain files are retained.

Use `--storage-mode full`, `variant_storage_mode: full`, or **Keep all work
files** to opt out. An explicit CLI value overrides YAML only for that run;
otherwise saved YAML settings are respected. Custom workflow bundles require
full storage. See [storage behavior and receipts](../variants.md#save-work-space-while-preserving-resume).
QUILT2 retains its prepared reference and chunk checkpoints and continues its
existing automatic cleanup of temporary imputation workspaces.

Cohort merging remains enabled by default and is optional through
`--no-merge-vcfs`, `variant_merge_vcfs: false`, or the browser checkbox.
Completed per-sample VCFs, indexes, annotations and reports remain available.
Re-enable merging to build cohort outputs from verified completed samples.

All application packages and the Nextflow manifest use version `2.3.1`.
Scientific environment definitions and the bundled GLIMPSE2/QUILT2 workflows
are unchanged. Nextflow runtime 26.04.2 remains pinned and authenticated.
Application-only upgrades preserve compatible scientific stage signatures;
changed inputs, tools or outputs still invalidate reuse.

Publication requires successful local Fresh, FFPE and ONT studies with full
output validation, plus Native v2 CI and both full CNA parity workflows for
the exact release source on main. Local package and scratch-cleanup tests do
not replace those gates. Until they pass, version 2.3.1 is a release candidate
and its artifacts must not be advertised as a published stable release.

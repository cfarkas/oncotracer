# OncoTracer 6.0.0

Version 6 adds one-command project creation from a sample table. The current
repository organization and historical benchmark examples are retained.

```bash
oncotracer launch --samples samples.csv --project my-run --specimen fresh
```

The [launch guide](../launch.md) covers Illumina, FFPE, ONT signal and existing
modified-base BAMs. No hand-written YAML is needed for these managed profiles.
The detailed YAML is still saved for review and advanced use.

## What changed

- One CSV/TSV supplies sample identifiers, input paths, roles and tissue routing.
  Duplicate physical inputs and conflicting sample assignments are rejected.
- Docker supplies the permitted scientific runtimes, including Rockfish,
  MARLIN, Modkit and isolated Sturgeon dependencies. MARLIN's original model
  and references are included with attribution.
- Dorado and Sturgeon are prepared in a private cache. Sturgeon requires the
  user's acknowledgement of its upstream license. ANNOVAR remains separately
  licensed and optional.
- Resource downloads use pinned sizes/hashes, resumable transfers and verified
  cache reuse. Failed preparations do not silently start an analysis.
- CPU and RAM are allocated from available hardware. GPU methylation checks
  Docker GPU access before preparing resources.
- Full ONT launch selects caller profiles from FASTQ model metadata. Missing
  metadata requires `--ont-profile`; mixed or conflicting profiles stop early.
  SUP v5.2.0 has its own verified Clair3 model, without changing older profiles.
- Docker methylation works in both terminal and browser setup. The obsolete
  backend restriction and conflicting documentation have been removed.

The CNA/variant algorithms retain the ichorCNA fallback, Broad profiles, coarse
rescues and platform-specific callers/imputation. Rockfish remains the default;
Modkit remains selectable. Insufficient coverage still produces an explicit QC
outcome rather than a confident classification.

## Runtime identity

The managed Dorado download is the public standalone **1.1.1+e72f1492** build.
The historical v5 benchmark used MinKNOW's **1.1.1+3c7eef9** build. They are
different executable builds, although both report 1.1.1. Asset receipts retain
this distinction; the old benchmark is not attributed to the new binary.

MARLIN uses the same pinned v1 model and hg38 features/probes. The public image
does not include Sturgeon code/model. Its private installation uses the pinned
upstream 0.5.1 interface; the isolated Python 3.9 dependencies reflect that
upstream requirement.

## Validation and historical benchmarks

Release candidates must pass the native CI, public-data parity gates, container
runtime checks and the new launch/resource tests before publication. Exact
commit hashes, artifact checksums and validation identities accompany the
published release.

The [58-sample study](../benchmarks/2026-11-23.md) and its downloadable bundle
remain **v5 measurements**. They document real runs and resources for that
version. They do not establish v6 runtime, diagnostic accuracy or a speedup.
The [v5 release page](5.0.0.md) is unchanged.

Use a new output directory for v6. Keep the original version/image when resuming
v5 results, and preserve their configuration and provenance.
